The DPM role, in a nutshell

A quick orientation before you dive in. Each card links to the full detail.

A Delivery Project Manager (DPM) owns a customer's network delivery from the moment an order is placed through to final handover — the single point of accountability that turns a signed order into working infrastructure on the customer's site, on schedule, on scope, and clearly communicated the whole way.

🗂️

Own the delivery

Drive each project from kickoff to HOTO sign-off — planning the timeline, tracking milestones, and managing orders in GOLD, ServiceNow, and SALTO.

🤝

Coordinate the teams

Orchestrate everyone the delivery depends on — VPOs and engineering, Field Engineers booked via FLIP, logistics, and the customer's technical contacts.

📊

Manage scope & risk

Keep everyone aligned: confirm prerequisites, flag blockers early, run staging and dry runs, and document decisions as you go.

🔧

Run the migration

Execute LAN and WAN migrations — switches, WLCs and APs — manage UAT with the customer, then close out every system once the site is live.

The delivery lifecycle

Every project follows the same three phases. The LAN and WAN process guides break each one down step by step.

Phase 1

Pre-migration

Confirm supply, raise MACHX, validate prerequisites, stage hardware, and run dry runs with the customer.

Phase 2

Migration

Execute the cutover on the agreed window, support the field/VPO teams, and run UAT on every migrated service.

Phase 3

Post-migration / HOTO

Send the success notification, update DNAC/CMDB, upload the HOTO pack, and close the GOLD and SALTO orders.
