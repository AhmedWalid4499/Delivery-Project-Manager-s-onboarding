📐 How this was calculated

    What is DHCP Option 43?

    When an access point (AP) boots, it needs to find its Wireless LAN Controller (WLC) — the brain that manages it. DHCP Option 43 is a vendor-specific field in the DHCP offer that hands the AP one or more controller IP addresses automatically, so the AP can join the WLC with zero manual configuration. Without it (or DNS-based discovery), a freshly-powered AP has no idea where its controller lives.

    📡

    AP boots & sends DHCP Discover

    The AP broadcasts a request — it needs an IP address and, crucially, a path to its controller.

    🏷️

    DHCP server includes Option 43

    The DHCP scope is configured to attach a vendor-specific hex payload pointing at the WLC IP(s).

    🔗

    AP decodes it & joins the WLC

    The AP parses the hex, extracts the controller IP(s), and opens a CAPWAP tunnel to the WLC.

    How Cisco encodes it — TLV

    Cisco uses a TLV (Type · Length · Value) structure inside Option 43. Every byte is hex-encoded:

    T

    Type — 0xF1

    Cisco sub-option 0xF1 (241) means "WLC address list". It tells the AP the following bytes are controller IPs.

    L

    Length — N × 4

    Each IPv4 address is 4 bytes. Two WLCs → length 0x08. Tells the AP how many bytes to read.

    V

    Value — IPs as hex

    Each IP is converted octet-by-octet: 192.168.1.100 → C0A80164. Concatenated, no separators.

    # Example — single WLC at 10.0.0.1 F1 04 0A 00 00 01 # F1 = sub-option · 04 = length (1 IP × 4 bytes) · 0A000001 = 10.0.0.1 in hex # Cisco IOS DHCP scope: option 43 hex f1040a000001
    💡

    Verifying Option 43 is a critical pre-migration step in the AP migration process — if it's missing, APs get an IP but never find the WLC. See the Wireless page for the discovery order (Option 43 → DNS → broadcast).
